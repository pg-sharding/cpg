Subject: [DRAFT UNSENT] Required-entry heap prototype: wide-OR SQL measurements

Hi,

I measured ordinary SQL equivalents of seven previously tested GIN AM unions
using an unchanged required-entry heap prototype. The heap selects the next
required entry for keys with at least eight required entries, with fuzzy search
disabled. It repairs copied monotone lower bounds rather than sorting mutable
shared-entry pointers. Tiny cases and fuzzy reduction keep the existing path.
This is an independent alternative over fixed historical B72, not a series
with the memo/startup/decoder experiments. No new production code was added
for this SQL follow-up.

The exact old AM predicates at widths1/2/7/8/32/128/512 became
SELECT count(*),sum(id) statements. A Seq control remains. All positive cases
force GIN and return200000 rows, so this demonstrates the selected GIN path,
not a default-planner application improvement. A selective natural-planner
workload remains a separate question.

Two fresh cohorts completed384 raw /288 retained /96 warm observations.
B/T are exact executable twins; all six role orders, three pairs and six
retained rounds are preserved. Literal count/sum, ordered Seq/GIN digests
and full measured plans/rows/loops agreed. Independent arithmetic and root
replay checked8208 numerical fields,144 absolute groups,144 pair groups
and864 direct pairs. All nine new smoke/accepted cluster lifetimes stopped;
held source/install/seed/input identities stayed unchanged.
