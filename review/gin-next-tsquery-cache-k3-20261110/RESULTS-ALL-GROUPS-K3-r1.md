## Scope and prior work

Full B/K1/K3/K3_assert source/header/production-compiler/core/native-dispatch and ordinary SQL/generic-fallback qualification must precede this screen. The source only opts into exact known builtin support OIDs and function addresses; arbitrary opclasses and shim paths retain their callbacks. It stores a single bounded ternary vector and complete FALSE/TRUE/MAYBE result for one scan-key lifetime, preserving native tri recheck state. K3 disables this memo after 64 consecutive dispatcher misses and resets the counter on a memo hit. The threshold counts dispatcher calls, including startup probes, rather than output TIDs. A long no-reuse prefix can still disable later reuse. The independent boundary helper checks 63/64/65 misses, hit reset, permanent direct dispatch and fresh-key context lifetimes; the original exhaustive oracle supplies mixed-vector coverage. Native context reset is separate from actual AM rescan. The untimed repetition probe was not latency evidence.

Consistent-result caching was already proposed in [Heikki 2014](https://www.postgresql.org/message-id/52F373CC.4050800%40vmware.com). This bounded prototype makes no novelty claim for that idea. Complete build/cleanup/source-freeze receipts and raw reproduction scripts must accompany the final artifact. This renderer itself creates no performance observation.
