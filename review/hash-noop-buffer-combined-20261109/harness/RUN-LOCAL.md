# Explicit root-owned local controller

`run-local.py` is new local code, AST/help checked only. It has not started a
server, copied PGDATA or run any SQL. Existing runner/common/protocol inputs
are unchanged. Root reviews/freezes this controller before explicit launch.

The runtime/fixture contract is the existing README/runtime.example schema.
Build receipts must be complete PASS_NEW_MATCHED_HASH_BUILDS with five installs
(B/N/H/C release and C assert),239core each. Runtime must be root APPROVED and
bind actual correctness/build/fixture receipts. It is not generated by the
controller. Build helpers are loaded from adjacent ../build-harness/common.py
(or explicit --build-tools) and their exact SHA is included in the controller
freeze. The controller checks actual full installed inventories,907headers/
install,7726source files, exact source-plan snapshots, support, holdout and
full-multiset receipts, seed and frozen benchmark inputs before/after stages.

Use new nonexistent output paths. The caller's allowed affinity must include
all chosen CPUs; do not taskset the whole controller to only its client CPU.
Default measured backend/client assignments6/4 then7/5 are read-only topology
recorded and required to use distinct guest physical cores within each pair.
Controller, pg_ctl and child runners retain/inherit the full original allowed
affinity; postmasters/background workers also inherit that full set. runner.py
first checks that both requested CPUs are allowed, then pins its own client
and measured backends. Inherited/full and actual postmaster affinity are
recorded; background placement is not claimed pinned. All are nice10; the controller and children inherit an
address-space soft limit of at most2560000000bytes. No kernel/ASLR/foreign
process setting is changed. Free disk must fit five additional seed copies
plus1GiB. Unix socket names must fit104bytes; keep output paths reasonably short.

First run ONLY smoke:

```sh
python3 -B harness/run-local.py --smoke-only \
  --runtime /ABS/R/runtime.json --fixture /ABS/R/fixture/fixture-receipt.json \
  --output /ABS/R/bench-smoke-r1
```

All ten accepted copies must initially be stopped and byte-identical to the
frozen seed. Five EXTRA smoke copies are created/hash-verified/fsynced before
the recorded role assignment. Numeric smoke births are B/T/N/H/C and ports
40600..40604. Smoke uses all19cases×5roles=95commands with zero accepted
timing. All own smoke postmasters/clients stop; seed and all ten UNUSED
accepted copies are rechecked unchanged. The controller then finishes as
PASS_SMOKE_AWAIT_ROOT_RUN_REVIEW. It never automatically starts an accepted
cohort. Source/runtime/frozen files,16cluster states and recorded own PIDs
must pass final guards; any failure stays a separate preserved attempt.

Root independently audits the complete smoke/plans/loops/answers and writes
a separate review JSON with status APPROVED and these exact hashes:

* smoke_outer_status_sha256: bench-smoke-r1/status.json
* smoke_status_sha256: bench-smoke-r1/smoke/status.json
* smoke_freeze_sha256: bench-smoke-r1/CONTROLLER-FREEZE.json
* unused_ten_sha256: bench-smoke-r1/UNUSED-TEN-AFTER-SMOKE.json
* runtime_sha256 and fixture_sha256: the same reviewed runtime/fixture files

Then root explicitly invokes ONLY the finite accepted run:

```sh
python3 -B harness/run-local.py --run-only \
  --runtime /ABS/R/runtime.json --fixture /ABS/R/fixture/fixture-receipt.json \
  --smoke-root /ABS/R/bench-smoke-r1 --review /ABS/R/PARENT-RUN-REVIEW.json \
  --output /ABS/R/bench-run-r1
```

The source/controller/runtime/fixture freeze, CPU assignments and port base
must match smoke. All ten accepted copies are rechecked stopped/unchanged
before launch. Cohort0 slot births B/T/N/H/C use40605..40609; cohort1 births
C/H/N/T/B use40610..40614, with reversed cases and swapped CPUs. Each cohort
gets five own persistent sessions and its own raw/status/backends files.
Exactly2280raw/1900retained/380warm are accepted across the two cohorts.
No build, profiling, source tuning, repeat or analysis is launched afterward.

Cleanup registers ownership before every pg_ctl start, including a failed/
timed-out startup. On any error it attempts each registered cluster stop
independently with its matching prefix, validates PID/executable/PGDATA before
signalling through pg_ctl, proves status3/clean shut-down/PIDfile absence and
fsyncs the stopped copy. The controller tracks only its own child ancestry;
every recorded own process must be absent at finish. It also checks all16
seed/accepted/smoke cluster states, full installs/source/support/seed/freeze,
and fsyncs seed/results. Cleanup errors preserve the original failure and
remain explicit in status.json. Nothing removes a failed directory or retries
performance. Full runner/server logs and PGDATA are local-only, excluded from
publication; compact birth/cleanup/freeze/PID proofs and raw observations are
the reviewable outputs.

Prefreeze review corrected an inherited-affinity defect: pinning the outer
controller to its client CPU before spawning runner.py would make the child
reject its requested server CPU. The outer pin was removed before any runtime;
the existing runner CPU/topology guard is unchanged. Child commands have
DEVNULL stdin, explicitly closed inherited descriptors, their own process
group, bounded waits and preserved original errors if termination cleanup
also fails. pg_ctl status and pg_controldata checks each have15-second limits.
