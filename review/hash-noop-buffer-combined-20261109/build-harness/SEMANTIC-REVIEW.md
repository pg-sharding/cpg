# Composition review: B72 / no-op / buffer hint

This review concerns only the exact public B72 alternatives N `3fc5ad43e3f932374ad4eb1fa7e2da041e5ffc3b`, H `989ba16d4557d01e9d0cf71dcf2ffe729b750f37`, and their normal cherry-pick composition C `909e76d48524f5f2c9bfed09c01f25195fb1798a`. No new production algorithm, threshold, fallback, cache lifetime or API repair is proposed. These are alternatives for a matched additive comparison, not an upstream patch series.

The two changes are semantically compatible at source level. N removes two calls to the B72 always-true qualification stub after saved-hash equality, one in each direction of the tuple loader. H initializes per-scan nonowning buffer/block hints and supplies them at the initial bucket acquisition. Its ReadRecentBuffer hit still obtains an ordinary pin, content lock and page check; its normal getbuf fallback, metapage-refresh/split-retry loop and release behavior remain. N neither accesses nor changes hint fields; H does not change the two loader selection conditions. In C, the other four H-edited files are byte-identical to H, and hashsearch.c is exactly H with N's two predicate removals. Both application orders reproduce the same five complete C snapshots with strict, zero-fuzz data-only patch replay.

This establishes compatibility of the selected source edits, not runtime correctness, memory safety, split concurrency or performance. In particular, H changes HashScanOpaque layout. Every production object and oracle must compile against its own role's installed headers; an old B/N module cannot attest H/C by substituting a new ELF pathname. The pure fixture custom-hash support library has no HashScanOpaque dependency and can be built once against B.

For this unchanged composition, root selected the following finite ordinary gate before accepted timing. Broader independent release qualification remains separate:

1. Five actual fullclean builds, B/N/H/C release and C assertions, with common paths/flags and all 239 unchanged core cases per build. Preserve expected files. Capture normal production objects/ASM: N/C must have the two no-op loader calls removed, H/C must preserve the actual hinted-getter path and ordinary fallback. No benefit is inferred from code size or frame changes.
2. A complete-production-TU page loader oracle, normal and UBSan, using each role's own headers. Compare both directions with an independent linear TID/offset/state reference on valid tuple/dead/moved/split/population combinations. Include NULL/empty and unsigned hash boundaries, duplicates, zero/MAX fixture hashes, and unchanged input pages. State comparisons must respect each role's layout, including initialized H/C hint fields. No fault-injection or arbitrary malformed-page campaign is required here.
3. Exact sequential/index full multisets and independent literal/formula scalar answers for all 19 fixed SQL cases on each release role and C assertions; enforce the actual natural residual 3000 index loops with Memoize enabled, retain the ordinary hot Memoize one-loop control and explicit disabled-Memoize 3000-loop control. Persist actual plans and heap-recheck/page counters. The seed verifier is B-only preparation and does not replace this all-role gate.
4. Five fresh disposable qualification clusters for the unchanged 126 logged/unlogged/TEMP insert-delete-VACUUM-REINDEX-TRUNCATE-refill checks and 21 SCROLL forward/backward/forward traces per role. These check full row multisets against the existing independent Python/formula reference and ordinary same/different/missing-key scans. They exercise normal AM behavior but do not directly instrument buffer-tag replacement, split-retry paths, hint-hit counts or all scan lifetime transitions.

The previous H-parent stale-hint, replacement and concurrent writer/reader evidence remains separately recorded historical evidence; it is not rerun or transferred to C as a new proof. New replacement/concurrency instrumentation is outside this fixed gate and would require a separately reviewed further release-qualification campaign, not an additional prerequisite silently attached to this finite benchmark screen. No concurrency, complete hint validation or general merge qualification follows from these serial checks.

Qualification must precede root's matched B/T/N/H/C runtime approval and smoke. T is the exact B installation/entrypoint on a separate postmaster, not a second baseline build. Qualification must use separate disposable clones so that the ten measurement copies remain stopped and unmodified before their prospective role assignment. Any failure is retained; no expected file is resnapshotted from C.
